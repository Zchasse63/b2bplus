# B2B+ Maintenance Guide

## Overview

This guide documents how to maintain and update B2B+ as the codebase evolves.

## Analysis Artifacts

### Database Analysis

**File**: `database_analysis.json`

Generated by:
```bash
npm run analyze:db
```

Contains:
- Table schemas
- Column definitions
- RLS policies
- Indexes
- Foreign keys

**When to regenerate**:
- After running migrations
- When adding new tables
- When modifying RLS policies
- Monthly as part of maintenance

### Implementation Analysis

**File**: `IMPLEMENTATION_TASKS_2025-11-19.md`

Contains:
- All audit findings
- Task breakdown
- Implementation steps
- Acceptance criteria

**When to update**:
- After completing major features
- When security issues are discovered
- Quarterly review

## Common Tasks

### Adding a New API Endpoint

1. Create route file: `apps/web/app/api/[domain]/[action]/route.ts`
2. Add auth check (user, admin, or public)
3. Add CSRF protection if mutating
4. Add input validation
5. Add error handling
6. Add structured logging
7. Update `docs/API_AUTH_MATRIX.md`
8. Add tests in `__tests__/api/`

### Adding a New Database Table

1. Create migration: `supabase/migrations/[timestamp]_[description].sql`
2. Define RLS policies
3. Add indexes if needed
4. Run migration: `supabase db push`
5. Update `database_analysis.json`
6. Document in `docs/ARCHITECTURE.md`

### Updating RLS Policies

1. Review current policies in `docs/RLS_AUDIT.md`
2. Create migration with new policies
3. Test with real data
4. Update documentation
5. Deploy and monitor

### Adding a New Service

1. Create service file: `apps/web/lib/services/[service].ts`
2. Export public functions
3. Add error handling and logging
4. Add JSDoc comments
5. Create tests in `__tests__/services/`
6. Document in `docs/ARCHITECTURE.md`

## Security Checklist

Before deploying to production:

- [ ] All API routes have auth checks
- [ ] All mutating routes have CSRF protection
- [ ] All webhooks verify signatures
- [ ] Service-role key not exposed
- [ ] RLS policies are correct
- [ ] Rate limiting is in place
- [ ] Error messages don't leak sensitive info
- [ ] All tests pass
- [ ] Security regression tests pass

## Deployment Process

1. Create feature branch
2. Make changes
3. Run tests: `npm run test`
4. Run security tests: `npm run test:security`
5. Create PR with description
6. Get code review
7. Merge to main
8. Deploy to staging
9. Run E2E tests
10. Deploy to production

## Monitoring

### Key Metrics

- API response times
- Error rates

- Database query performance
- Auth success rates

### Tools

- Sentry: Error tracking
- Vercel Analytics: Performance
- Supabase Dashboard: Database metrics
- SendGrid Dashboard: Email delivery

## Troubleshooting

### High Error Rate

1. Check Sentry for error patterns
2. Review recent deployments
3. Check database performance
4. Review webhook logs
5. Rollback if necessary

### Slow API Responses

1. Check database query performance
2. Look for N+1 queries
3. Review caching strategy
4. Check external service latency
5. Consider adding indexes

### Webhook Failures

1. Check webhook logs
2. Verify signature verification
3. Check rate limiting
4. Review database RLS
5. Check external service status
